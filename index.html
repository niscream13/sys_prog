Системи контролю версій та Git

Система контролю версій (VCS) — це програмне забезпечення, яке дозволяє відстежувати зміни у файлах проєкту, зберігати історію їх редагування та за потреби повертатися до попередніх версій.

Git — це розподілена система контролю версій, створена для ефективної роботи з програмними проєктами. Кожен розробник має локальну копію репозиторію разом з історією змін, тому більшість операцій можна виконувати без постійного підключення до сервера.

Git часто використовується разом із сервісами для зберігання віддалених репозиторіїв, наприклад GitHub, GitLab або Bitbucket.

Основні можливості та переваги Git

Git надає розробникам зручні інструменти для керування кодом та спільної роботи над проєктами.

01

Історія змін

Git зберігає попередні версії проєкту та дозволяє переглядати внесені зміни.

02

Гілки

Можна створювати окремі гілки для нових функцій, не змінюючи основну версію.

03

Командна робота

Декілька розробників можуть одночасно працювати над одним проєктом.

04

Локальна робота

Більшість операцій Git не потребують підключення до Інтернету.

05

Відновлення версій

За необхідності можна повернутися до попереднього стану проєкту.

06

Швидкість

Git ефективно працює навіть з великими проєктами та історією змін.

10 базових команд Git

Невеликий набір команд для початку роботи з репозиторієм.

  1. git init

    Створює новий локальний Git-репозиторій у поточній папці.

  2. git clone <URL>

    Завантажує існуючий віддалений репозиторій на комп'ютер.

  3. git status

    Показує поточний стан репозиторію та список змінених файлів.

  4. git add <file>

    Додає вибраний файл до області підготовки. Для всіх змін: git add .

  5. git commit -m "message"

    Зберігає підготовлені зміни в історії Git разом із коротким описом.

  6. git log

    Показує історію комітів репозиторію.

  7. git branch

    Показує список гілок. git branch <name> створює нову гілку.

  8. git switch <branch>

    Перемикає користувача на іншу гілку.

  9. git pull

    Отримує актуальні зміни з віддаленого репозиторію та інтегрує їх у локальну гілку.

  10. git push

    Відправляє локальні коміти до віддаленого репозиторію.
